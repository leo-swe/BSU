Основные компоненты серверного приложения


Backend разработка — это процесс создания и поддержки
серверной части, которая обрабатывает пользовательские
запросы, обеспечивает работу с базами данных, управляет
бизнес-логикой и взаимодействует с различными внешними
сервисами.



Отвечает за:


Обработку пользовательских запросов и передачу соответствующих данных
в клиентскую часть (Frontend).



Управление базами данных и хранение информации, необходимой для
работы приложения.



Обеспечение безопасности данных и защиту от угроз.



Взаимодействие с API и сторонними сервисами для расширения
функциональности приложения.

Основные компоненты серверного приложения


Серверы и хостинг.
Серверы представляют собой мощные компьютеры или системы, которые
хранят и обрабатывают данные веб-приложения. Выбор подходящего
хостинга и настройка серверов важны для обеспечения стабильной и
быстрой работы сайта.



Языки программирования и программные средства (фреймворки).
Backend разработка может быть выполнена с использованием различных
языков программирования, таких как Python, Node.js, Ruby, PHP и других.
Фреймворки представляют собой набор инструментов и библиотек, которые
облегчают процесс разработки и ускоряют создание веб-приложений.



Базы данных и их роль в реализации серверной части (backend).
Базы данных играют ключевую роль в Backend разработке. Они
используются для хранения и управления данными приложения, такими как
пользовательские профили, товары, заказы и другая информация.
Правильный выбор типа базы данных и её эффективное использование
способствуют оптимизации производительности и расширяемости
приложения.

Преимущества разработки серверного приложения








Улучшение производительности сайта.
Оптимизация бизнес-логики способствует более быстрой загрузке страниц и
обработке пользовательских запросов. Это важно для удовлетворения ожиданий
пользователей, так как быстрые и отзывчивые сайты повышают удовлетворенность
и удержание пользователей.
Расширяемость и масштабируемость.
Хорошо спроектированное серверная часть приложений обеспечивает гибкость и
масштабируемость веб-приложения. При увеличении количества пользователей и
объёма данных, позволяет безболезненно масштабировать инфраструктуру и
поддерживать высокую производительность.
Разделение обязанностей (Frontend vs. Backend).
Клиентская и серверная часть выполняют разные функции и разделяют
обязанности, что позволяет создавать более эффективные команды разработчиков.
Frontend-разработчики занимаются визуальным представлением и
пользовательским интерфейсом, в то время как Backend-разработчики работают с
данными и логикой приложения.
Обеспечение безопасности данных.
Серверное приложение ответственно за обеспечение безопасности приложения и
данных пользователей. Он должен защищать информацию от
несанкционированного доступа, предотвращать атаки и обеспечивать
конфиденциальность чувствительных данных.

Технологии проектирования серверной части


MySQL — это одна из наиболее популярных реляционных баз данных. Она
характеризуется высокой производительностью и надёжностью, что делает
её хорошим выбором для различных типов приложений. Выпущена в 1995
году.
 MariaDB — это модифицированная версия MySQL. Сервис MariaDB был
создан первоначальной командой разработчиков MySQL из-за проблем с
лицензированием и распространением после того, как базу данных MySQL
приобрела корпорация Oracle. В 2009 году разработчики выпустили
MariaDB в качестве форка кода MySQL 5.1.38.




В MariaDB сохраняется структура MySQL, соглашения об именах и файлы определений
данных. Кроме того, сервис поддерживает все коннекторы, соединения и порты MySQL.
Ваш клиентский пакет MySQL работает с MariaDB без изменений.

PostgreSQL — это мощная и расширяемая реляционная база данных. Она
предлагает множество возможностей и поддерживает сложные запросы и
транзакции.
 MongoDB — это документоориентированная нереляционная база данных,
которая хранит данные в формате BSON (бинарный JSON). Она особенно
подходит для проектов с изменяющейся схемой данных.

Node.js
Node или Node.js — серверная среда с открытым исходным кодом которая
использует JavaScript на сервере. Основана на программном средстве V8
(транслирующем JavaScript в машинный код), превращающая JavaScript из
узкоспециализированного языка в язык общего назначения. Разработана в
2009 г. Райном Далем.
Node.js добавляет возможность JavaScript взаимодействовать с
устройствами ввода-вывода через свой API (написанный на C++),
подключать другие внешние библиотеки, написанные на разных языках,
обеспечивая вызовы к ним из JavaScript-кода.
Express.js — это быстрый, гибкий и минималистичный веб-фреймворк для
Node.js. Фактически это инструмент, упрощающий создание вебприложений и API с использованием JavaScript на стороне сервера.

PHP & Laravel
 Основные компоненты Laravel:


Маршрутизация — сопоставление входящих URL-адресов с
соответствующими действиями контроллера в каталоге routes. Эти
маршруты определяют, как приложение реагирует на запросы
пользователей.



Контроллеры: Контроллеры обрабатывают входящие запросы,
обрабатывают данные, взаимодействуют с уровнем модели и определяют
ответ приложения. Контроллеры находятся в app/Http/Controllers каталог.



Модели: Модели представляют данные приложения и бизнес-логику.
Взаимодействуют с базой данных с помощью Eloquent и инкапсулируют
логику доступа к данным. Модели обычно определяются в app/Models
каталоге.



Представления: Представления отвечают за создание пользовательского
интерфейса. Laravel использует средство создания шаблонов Blade,

Django


Django — программное средства на основе Python для разработки вебприложений. Предоставляет встроенный интерфейс, включая
интерфейс администрирования, базу данных по умолчанию на основе
SQLite3.



Представления (View) являются основой Django для обработки
запросов пользователей и отображения ответов.


Основаны на двух парадигмах реализации:



На основе функций (Function Based Views — FBVs)
На основе классов (Class Based Views — CBVs)



Для построения URL Django использует шаблоны, которые являются
важным механизмом для направления входящих запросов к
соответствующим представлениям в веб-приложении.



Модели Django служат основой операций с базами данных и являются
функционалом объектно-реляционного отображения Django.

Как выбрать подходящий стек технологий


Учитывать требования проекта и его характеристики.
Оцените характер проекта, его объём данных, требования к
производительности, безопасности и масштабируемости. Исходя из
этого, выберите технологии, которые наилучшим образом
соответствуют потребностям вашего проекта.



Оценить опыт команды разработчиков.
Учитывайте опыт и знания команды разработчиков. Если у вашей
команды уже есть опыт работы с определенными технологиями, это
может существенно ускорить разработку и повысить качество кода.



Рассмотреть факторы масштабирования и будущего развития.
Учитывайте возможности масштабирования вашего проекта в будущем.
Выбирайте технологии, которые позволят легко расширять
функциональность приложения и обрабатывать увеличивающуюся
нагрузку.

Практики безопасной разработки серверных приложений
Ключевые шаги безопасной разработки:


Шаг 1. Защита от XSS: Для
предотвращения XSS необходимо
экранировать выводимые данные,
используя функции, которые преобразуют
специальные символы в HTML-сущности.



Шаг 2. Защита от CSRF: использовать
специальные токены, которые уникальны
для каждого запроса



Шаг 3. Контроль доступа: проверять права
пользователя перед предоставлением
доступа к ресурсам, чтобы избежать
уязвимостей IDOR/Broken ACL



Шаг 4. Не хранить конфиденциальную
информацию в открытом виде



Шаг 5. Защита от SQL-инъекций:
использовать подготовленные выражения,
чтобы гарантировать, что пользовательский
ввод будет экранирован и не
интерпретируется как часть SQL-запроса
