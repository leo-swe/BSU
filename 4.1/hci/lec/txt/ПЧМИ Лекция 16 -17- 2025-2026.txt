

Текущий стандарт ECMAScript определяет шесть типов данных, которые
являются примитивами:


Логический (boolean): true и false.



Null: Специальное ключевое слово, обозначающее нулевое или «пустое» значение.
Поскольку JavaScript чувствителен к регистру, null не то же самое, что Null, NULL или любой
другой вариант. В JavaScript, null является примитивом, и в контексте логических операций,
рассматривается как ложное (false).



Неопределенный (undefined): Свойство глобального объекта; переменная, не имеющая

после создания строкового значения его нельзя модифицировать.

уникальность. Символы часто используются в качестве уникальных ключей объекта.

Поднятие переменных






В JavaScript можно сослаться на
переменную, которая объявляется позже, и
не получить при этом исключения.
Данная концепция известна как поднятие
(hoisting) переменных; переменные в
JavaScript поднимаются в самое начало
функции или выражения.
Переменные, которые ещё не были
инициализированы, возвратят значение
undefined:

/*
* Example 1 – Поднятие переменных
*/
// Вариант 1
console.log(x === undefined); // true
var x = 5;
// вариант 2
console.log(x === undefined); // true
var x = 5;

Концепция Hoisting в JavaScript — это
механизм, при котором объявления
переменных и функций перемещаются
("поднимаются") вверх своей области
видимости во время компиляции, до
выполнения кода.
Независимо от того, где переменные и
функции объявлены, они становятся
доступны в начале своей области
видимости.

/*
* Example 2 – Поднятие переменных
*/
var myvar = "my value";
(function () {
console.log(myvar); // undefined
var myvar = "local value";
})();

Поднятие переменных
 Из-за поднятия переменных, все операторы var в функции

следует размещать настолько близко к началу функции,
насколько это возможно.

 В ECMAScript 2015, let (const) не будет подниматься вверх

блока. Однако, ссылки на переменную в блоке до объявления
переменной вызовут ReferenceError. Переменная находится
во «временной мёртвой зоне» (Temporal Dead Zone, TDZ) в
начале блока, до момента объявления.

function do_something() {
console.log(foo); // ReferenceError
let foo = 2;
}

Итерации


do...while — создаёт цикл, выполняющий указанную инструкцию до тех пор,
пока проверяющее условие равно false. Условие вычисляется после
выполнения инструкции, так что указанная инструкция выполнится хотя бы
один раз.
 for — создаёт цикл, состоящий из трёх необязательных выражений,
заключённых в круглые скобки и разделённым точками с запятой с
последующей инструкцией, выполняющейся в цикле.
 for...in — в случайном порядке проходит по перечислимым свойствам
объекта. Выполняет инструкции для каждого уникального свойства.
 Экспериментальная возможность for...of — проходит по итерируемым
объектам (включающим в себя массивы, массивоподобные объекты и
итераторы с генераторами), выполняя пользовательский хук с
инструкциями, исполняющимися для значения каждого уникального
свойства.
 while — создаёт цикл, выполняющий указанную инструкцию до тех пор,
пока проверяющее условие равно true. Условие вычисляется перед
выполнением инструкции.

 Метод addEventListener
 Свойства объекта

События и обработчики событий


Использование атрибутов HTML
Этот способ позволяет назначить обработчик события непосредственно
в HTML-коде элемента. Однако он имеет свои ограничения, так как не
позволяет назначать несколько обработчиков на одно событие и может
затруднить поддержку кода.

<button onclick="alert('Button clicked!')">Click
me</button>

События и обработчики событий
 Метод addEventListener является предпочтительным, так как он

позволяет назначать несколько обработчиков на одно событие и
предоставляет больше возможностей для управления
событиями. Этот метод также позволяет удалять обработчики
событий, что может быть полезно в некоторых ситуациях.

document.getElementById('myButton').addEventListener(
'click', function() {
alert('Button clicked!');
});

События и обработчики событий
 Свойства объекта — данный способ позволяет назначить

обработчик события с использованием свойства объекта.
Однако, как и в случае с атрибутами HTML, он не позволяет
назначать несколько обработчиков на одно событие.
document.getElementById('myButton').onclick =
function() {
alert('Button clicked!');
};

Пакетный менеджер PNPM
 Пакетный менеджер PNPM (PERFORMANT NPM) вышел в марте

2016 года. Автор — Zoltan Kochan.

 Менеджер пакетов PNPM решил проблему с объемом

занимаемого дискового пространства и недоступностью
зависимостей.


Что послужило толчком для разработчиков YARN создать Yarn Plug'nPlay
(Yarn PnP), который включен в YARN 2.

 PNPM выполняет все операции с пакетами атомарно, что

гарантирует, что все изменения зависимостей будут отменены,
если какая-то операция завершится неудачно.

 PNPM использует свой подход к установке зависимостей. На

начальном этапе концепция управления зависимостями
совпадала с npm, что не требовало переобучения.

Пакетный менеджер PNPM
Особенности PNPM:
 Скорость работы с пакетами за счет использования технологии установки
зависимостей «hard links», которая позволяет избежать копирования
дублирующихся файлов между пакетами.




PNPM создает на компьютере единый репозиторий npm-пакетов с контентно-адресуемой
файловой системой, подобной Git. Каждый файл в этой системе получает хэш от своего
содержимого, и файлы с одинаковым содержанием не повторяются. В папке node_modules
создаются символические ссылки на эти файлы, вместо того чтобы их каждый раз
копировать.

Возможность автозаполнения при работе с зависимостями.
Недостатки:
 Возможные проблемы с кроссплатформенностью, так как «hard links»
работают по-разному на разных операционных системах.
 Неподдерживаемые пакеты: некоторые пакеты могут не работать должным
образом с PNPM, потому что не поддерживают символические ссылки,
которые использует PNPM.
 Меньшая поддержка сообществом.

 Основная задача — пакетирование файлов JavaScript для
